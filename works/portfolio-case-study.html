01 — Overview

Built to move,
not just exist.

Most portfolios are static pages dressed with a few hover effects. I wanted something that felt alive — where every scroll gesture, every click, every page load was part of a deliberate motion language. This site is that attempt: a fully hand-coded personal portfolio with no framework, no UI library, no shortcuts.

Version 3 is a ground-up rebuild. Earlier versions were over-engineered with React and too many dependencies. Stripping back to vanilla HTML, CSS and JavaScript turned out to be the right call — faster, more controllable, and honestly more fun to build.

02 — The decision

Why no
framework?

V2 used React. It came with a fast dev experience but also a 130 KB+ bundle, hydration delays, and the constant friction of mapping animation libraries to component lifecycles. GSAP and React are a workable combination — but they fight each other's mental models.

Going vanilla meant full control over the DOM. GSAP's ScrollTrigger works against real DOM elements with no virtual-DOM indirection. Transitions happen in plain JS with no re-render cycles. The browser does exactly what I tell it to, nothing more.

The constraint became the feature. Without a framework's abstractions, every animation, every scroll interaction and every transition had to be explicitly designed. That's what makes the motion feel intentional rather than incidental.

03 — Hero animation

The 90-frame
scroll sequence.

The hero is a canvas-rendered image sequence — 90 JPEG frames extracted from a video at 30 fps, covering roughly 3 seconds of footage. As the user scrolls, ScrollTrigger maps scroll progress to a frame index and draws the correct image onto a full-viewport canvas.

indexa9ea.js — frame rendering 
// Map scroll progress → frame index → canvas draw
function drawFrameAtProgress(progress) {
  const clamped = Math.min(1, Math.max(0, progress));
  const loadedPos = Math.round(clamped * (totalFrames - 1));
  const sourceIdx = loadedFrameIdx[loadedPos];
  if (sourceIdx == null) return;
  drawFrame(sourceIdx);
}

// Cover-fit the frame to the canvas on every resize
function drawFrame(i) {
  const img = frames[i];
  const s = Math.max(cw / img.naturalWidth, ch / img.naturalHeight);
  ctx.drawImage(img,
    (cw - img.naturalWidth * s) * 0.5,
    (ch - img.naturalHeight * s) * 0.5,
    img.naturalWidth * s, img.naturalHeight * s
  );
}

Loading strategy matters a lot here. Fetching 90 images naively would saturate the network. Instead, the loader uses a three-phase strategy:

01
Frame 1 — immediate
The very first frame is fetched with fetchpriority="high" as a preload hint in the HTML head, so it is available before JS even runs. The canvas shows it instantly on paint.
02
Frames 2–10 — speed probe
The first batch of 10 frames is fetched and timed. If the batch takes over 2 seconds, a skip factor is set so only every Nth remaining frame is loaded — preserving smoothness on slow connections without blocking the page.
03
Frames 11–90 — background concurrent
The rest load concurrently (6 at a time on fast hardware, 2 on slow) using a worker-pool pattern. Each loaded frame updates a sorted index so the draw function always picks the closest available frame even mid-load.

On slow hardware a 32 ms frame-draw throttle is applied (dropping the effective update rate to ~30 fps) and the device-pixel-ratio is capped at 1× to halve canvas memory. The animation stays smooth even on budget phones.

04 — Scroll architecture

One timeline,
many layers.

The hero scroll is a single GSAP timeline scrubbed by ScrollTrigger. It coordinates six simultaneous animations — the name layers exit left and right, the tagline fades, the frame sequence plays in, a phrase reveal animates character-by-character — all locked to the same scroll progress value.

0%–30%
Name exit phase
The preloader name characters slide off-screen left and right while the tagline and navigation bar fade to zero opacity.
30%–100%
Reveal phase
The canvas scales up from zero as the frame sequence plays. A blurred phrase fades in character-by-character using a staggered GSAP tween on individually-wrapped span elements.
Exit
Section transition
As the next section scrolls into view, a second ScrollTrigger pushes the canvas upward with a parallax offset and applies a backdrop blur + dark overlay, creating a depth-of-field feel as the about section emerges.

Lenis provides smooth inertia scrolling. It wraps the native scroll events and re-dispatches them with a configurable easing curve, so ScrollTrigger receives fractional progress values even when the user flicks quickly.

The about section's text uses a word-level blur reveal — each word is wrapped in a <span class="word"> by a TreeWalker pass at runtime, then each span gets its own ScrollTrigger that transitions opacity and filter: blur() from 0 to 1 as it scrolls into the viewport center band.

"The best animation is the one the user doesn't consciously notice — they just feel like the interface responds to them."
05 — Page transitions

Leaving gracefully,
arriving deliberately.

Navigating between pages uses a two-panel wipe: a dark overlay panel slides up covering the current page, then after the new page loads a red accent panel wipes down to reveal it. This happens on any link marked with data-page-link.

The trick is that the transition timeline starts before the browser navigates. A click listener on those links calls e.preventDefault(), runs the exit animation (~600 ms), then uses window.location.assign() to navigate. On the destination page a reverse reveal animation fires on DOMContentLoaded, so both halves of the wipe feel like one fluid motion across the page boundary.

gsap-page.js — exit transition 
// Intercept navigation, animate out, then navigate
document.querySelectorAll('[data-page-link]').forEach(link => {
  link.addEventListener('click', e => {
    e.preventDefault();
    const dest = link.href;

    gsap.timeline()
      .set('#t-panel-dark', { scaleY: 0, transformOrigin: 'bottom' })
      .to('#t-panel-dark', { scaleY: 1, duration: 0.55, ease: 'power3.inOut' })
      .add(() => window.location.assign(dest));
  });
});
06 — Project overlay

Case studies
in-place.

Clicking a project on the homepage doesn't navigate away — it opens a full-screen overlay with a flying title animation. The project title element's bounding rect is captured at click time, cloned into a fixed-position layer, then tweened to its destination position in the overlay panel. The result feels like the title travels to become the overlay heading.

01
Flying title
The clicked title's position, font size and line height are read via getBoundingClientRect() and getComputedStyle(). A fixed-position clone is created and GSAP tweens it to the final overlay header position while the overlay fades in behind it.
02
Cylindrical 3D gallery
Project screenshots in the circle-gallery section are rendered as a cylindrical carousel using pure CSS 3D transforms. Each image is sliced into 10 vertical strips and each strip is rotated around a shared Y-axis with a calculated orbit radius, creating a bent-photograph effect without WebGL.
03
Scrollable thumbnail strip
The overlay's thumbnail strip uses a custom scroll handler driven by GSAP's quickTo for smooth Y-interpolation. The active thumbnail is determined each frame by measuring distance from the strip's center, and the selected large image updates to match — no click required.
04
3D image tilt
While an overlay is open, the selected project image tracks the mouse position and applies a rotateX/rotateY CSS transform, giving it a parallax card-tilt effect. The tilt values are smoothed with a lerp loop running in the GSAP ticker.
07 — Visual details

The fluid line
& micro-details.

The decorative SVG curve in the projects section is drawn using a strokeDasharray / strokeDashoffset technique. The path's total length is measured via getTotalLength() at init time, then ScrollTrigger scrubs the strokeDashoffset from the full length to zero as the section scrolls into view — making the line appear to draw itself.

The cursor changes contextually throughout the page. On project images it shows a small circular label. On links it shows a character string. These are implemented as a single custom cursor element repositioned with a lerp loop, switching CSS classes based on the element under the pointer via data-chr and data-cursor-img attributes.

Frame corners — those thin L-shaped brackets on images and buttons — are pure CSS. Each is a ::before and ::after pseudo-element on a .frame-corner span. No images, no SVGs. They transition colour on hover, synced with the image scale transform, giving the impression of a camera viewfinder locking on.

The site-pet (the small floating character) lives in its own isolated script and element layer. It uses a sprite-sheet animation loop and reacts to scroll state via a shared window.__hideSitePet flag set by the scroll timeline, so it disappears cleanly during the hero reveal without any direct coupling.

08 — Easter egg

The footer
skate game.

Hidden in the footer is a playable side-scrolling skate game rendered on a <canvas> element. Press Space or tap the canvas to jump. It was built as an experiment in keeping the site memorable — something a recruiter or collaborator might discover and actually pause on.

The game loop uses requestAnimationFrame with a fixed timestep and simple AABB collision detection. Obstacles are generated at randomised intervals with a difficulty ramp tied to the score. The player sprite is drawn frame-by-frame from a spritesheet using canvas drawImage with clipping coordinates.

Loop
requestAnimationFrame + fixed timestep
Physics and collision run at a fixed 60 Hz logical step, decoupled from the render frame rate. This keeps the game consistent on high-refresh displays without speeding up the physics.
Input
Keyboard, pointer & touch
Space, ArrowUp, click and touchstart all trigger a jump. A double-jump is allowed while airborne. The input handler ignores events when the game is over or paused to prevent ghost jumps.
Render
Canvas 2D sprite animation
The skater cycles through animation frames from a spritesheet, switching to a jump frame while airborne and a tumble sequence on death. Background parallax layers scroll at different speeds to create depth.
09 — Performance

Fast by
design.

A site this animation-heavy can easily become slow. Every architectural decision has a performance consideration attached to it.

Images
AVIF / JPEG with fetchpriority
Project covers are served as AVIF where supported (40–60% smaller than JPEG). The hero frame sequence uses JPEG for maximum decoder compatibility. The first hero frame carries fetchpriority="high" as a preload; all others are loading="lazy".
Canvas
DPR capping + throttle on slow hardware
A hardware speed probe runs during the first frame batch load. On slow devices the canvas DPR is fixed at 1× and draw calls are throttled to 32 ms minimum. A navigator.hardwareConcurrency check also reduces image fetch concurrency from 6 to 2.
JS
Deferred loading cascade
Non-critical scripts (core-renderer, hero-project, page-background) load in a chained cascade after window.load with a 400 ms delay, keeping the main thread free during the initial paint. GSAP and ScrollTrigger load with defer.
CSS
will-change used surgically
will-change: transform is applied only to the canvas element and the reveal sequence, promoting them to their own compositor layers. It is removed from elements once their animation completes to free GPU memory.
Motion
prefers-reduced-motion respected
A global prefersReducedMotion check at init disables blur filters and complex stagger animations site-wide. The site remains fully functional and readable with all motion off.
Fonts
WOFF2 preloaded, OTF fallback
Both custom fonts (Breton, Machine) are declared as <link rel="preload"> in the document head with crossorigin so they are fetched in parallel with HTML parsing and never block render.
10 — Design language

Dark, precise,
intentional.

The colour palette is a near-black background (#05070f) with a single blue accent (#1e6bff) used sparingly — on hover states, active indicators and interactive affordances only. Everything else is white at varying opacities.

Two typefaces do all the work. Breton (a geometric display serif) handles headings and body copy at all sizes. Machine (a monospaced techno face) appears in the .other-accent class — reserved for dates, version labels, the hero phrase and decorative numerals.

Spacing is viewport-relative throughout. Font sizes use clamp() with a fluid range between a minimum at 320 px and a maximum at 1400 px, so the typographic scale compresses gracefully without any breakpoint-specific overrides for type.

Aa
Breton — display & body
Geometric serif, weight 300. Used for headings, project titles, about text and all long-form prose.
Aa
Machine — accent & label
Monospaced techno face. Used for dates, version labels, the hero phrase, stat numerals and the in motion italic-styled accents.
Inter
Inter — UI & metadata
System-weight sans-serif. Used only for labels, tags, dates, counters and navigation — never for expressive copy.
11 — Lessons

What I'd do
differently.

01
The frame sequence is fragile on very slow connections
Even with the skip-factor loader, a user on a throttled 3G connection will see partially loaded animation. A future version should fall back to a CSS-animated static visual when the network is too slow, detected via the Network Information API.
02
The JS bundle could be split further
The main JS file handles too many concerns in one place. It grew organically section by section. A cleaner architecture would have each section (hero, about, projects, skills) as a separate module loaded on-demand as the user scrolls to that section.
03
Accessibility needs more attention
Most interactive elements have ARIA labels and keyboard support, but the canvas-based animations have no non-visual equivalents. A future pass should add a fully accessible text-only mode that disables the canvas entirely and presents the site as clean, readable prose.
04
The i18n system is underused
There's an internationalisation module (i18n.js) with translation support built in, but currently only a few strings use it. Either commit to full i18n — adding proper language switching UI — or remove the abstraction and keep the copy in HTML directly.
